# Cora installation and acceptance mission
Owner: Cora (operations). Reviewer: an independent runtime such as Bucky or Finch, scoped to actual access. This is a setup/test assignment, not merge, deployment or paid-turn approval.

## Prepare
- Pin a reviewed package commit and verify integrity. Read CONTRIBUTING.md. Existing branches and agent registrations remain authoritative.
- Create a PRIVATE installation directory or branch. Copy templates with exclusive creation; never overwrite an existing checkpoint. Git-ignore real local state if it resides near the public checkout.
- Inventory actual original sessions, Switch runner IDs/handles, owners, host adapters and room membership. Apply the display-name distinction only through supported settings after backing up current profiles. Do not register duplicates or rotate keys.
- Put the mandatory startup pointer in supported runner/room instructions. Upload or reference accessible approved documents. A link alone does not grant read permission or prove automatic startup loading.
- Map actual memory read/write tools for each runtime. Start with GitHub as relay/index. Record permission failures accurately; do not assume a room document can be edited by every agent.

## Two-runtime memory test
Use two isolated test sessions (two Finch sessions if available and already authorized). If invocation is held, prepare fixtures and return BLOCKED instead of spending.
1. Runner A writes a synthetic fact with source, uncertainty, revision and a checkpoint.
2. Runner B reads it from durable storage without prior chat, cites the source and distinguishes fact from inference.
3. A and B independently propose changes from the same revision. Require conflict rejection/reconciliation with original history preserved.
4. Restart A with a fresh context. Require correct identity, approved package SHA, last human decision, active mission and next action.
5. Correct a fact using supersedes; verify B finds the correction and does not silently erase the old record.
6. Delete or revoke a synthetic reference and verify the runner reports the missing source rather than inventing its contents.

## Wake integration test
Follow ACTIONS_INTEGRATION.md. Use manual dispatch first, exact recipient mapping and a synthetic mission. Prove transport → authenticated target ACK → private GitHub receipt. Re-deliver once, expire once, cancel once and simulate network failure. Keep delivery UNKNOWN for an ambiguous timeout. Do not invoke a paid agent to test transport while a spending hold applies.

## Settings and avatar inventory
For each exact model/host, report requested temperature, supported state, applied/effective evidence and reasoning mode. Unsupported/hidden is a valid finding; do not invent a setting. For avatars, give Gem deployed Console/Core versions and redacted request/status evidence, preserve the chosen original assets and test native versus UI rendering separately.

## Deliver
Post a private report with code SHA, environment, commands, actual counts, source/Action/Switch/ACK references, identity mapping, capability matrix, failures and next owner. Use ACCEPTANCE.md. Mark every unrun live check UNKNOWN. No merge, production deployment, access-policy widening, new schedule or paid activation is implicit.
